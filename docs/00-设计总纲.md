## 1. 一句话概念

> 你是一枚在电脑桌面里失控的光标，用一行行字符击碎满屏的软件图标，在系统崩溃前把 C: 到 G: 的磁盘全部关机。

**电梯陈述**：轻量、极简、可 3 秒开玩的 Roguelike 弹幕射击。桌面就是战场，软件图标就是敌人，RAM 就是命，蓝屏就是结算。单局 12–35 分钟，手机/电脑打开即玩，离线可用。

---

## 2. 设计支柱（所有取舍以此排序）

1. **桌面即战场**：一切元素都来自电脑桌面隐喻（磁盘、文件夹、图标、命令、蓝屏、关机）。隐喻要“贴切且有梗”，不能只是换皮文案。
2. **极简但不简陋**：单色背景 + 图标 + 等宽字符；用 3 种信息层级讲清一切，禁止堆 HUD。
3. **每 40 秒做一次选择**：短波次、快结算、增益三选一；决策密度高于操作长度。
4. **死得明白，赢得痛快**：受击/死亡必有清晰因果；死亡是蓝屏，通关是关机，情绪闭环完整。
5. **轻量到即时可玩**：首屏 ≤ 500 KB、无运行时网络请求、60 FPS、手机横屏即开即玩。

## 4. 核心循环

```
局外（桌面 Hub）
  碎片 ──► 抽取键帽 ──► 装入 87 键键盘 ──► 属性/套装提升
     ▲                                            │
     │ 结算                                        ▼
┌────┴──────────────────────────────────────────────────────────┐
│ 开机 → 选难度 → [ 磁盘 C: → 文件夹×5 → 根目录 Boss ] × N → 关机 │
│                        │              │                        │
│                  每关 3 选 1 增益   传奇增益 + 键帽 + 系数提升    │
│                        │                                       │
│                  死亡 → 蓝屏 → 结算                             │
└────────────────────────────────────────────────────────────────┘
```

- **微循环（3–8 s）**：移动光标 → 自动射击 → 走位躲弹 → 击杀。
- **中循环（30–60 s）**：一波怪 → 清场 → 下一波 → 关卡结算 → 三选一增益。
- **大循环（3–6 min）**：5 个文件夹 → 磁盘 Boss → 新磁盘/新风格。
- **元循环（12–35 min）**：一局结束 → 蓝屏/关机 → 碎片与键帽入库 → 键盘变强。

## 5. 局内结构

### 5.1 局（Run）

- 1 局 = 从“开机”到“蓝屏/关机”。局内一切增益、RAM、敌人刷新均**不跨局**。
- 磁盘序列固定从 `C:` 开始，按难度决定终点：
  - 节能：`C: D: E:`（3 层）
  - 平衡：`C: D: E: F:`（4 层）
  - 高性能：`C: D: E: F: G:`（5 层）
- 每层磁盘 = **5 个文件夹关 + 1 个根目录 Boss 关**。
- 每层磁盘通关后：`关卡系数 K` 提升（见 §7.3）、RAM 回满、进入下一磁盘。
- 每局 Boss 数量 = 磁盘数；每局传奇增益保底数量 = 磁盘数。

### 5.2 文件夹关

| 波次 | 基准构成 | 说明 |
| --- | --- | --- |
| W1 | 3 普通小怪 | 热身，0.6 s 间隔逐个刷出 |
| W2 | 5 普通小怪 | 混编 2 种行为 |
| W3 | 4 普通小怪 + 1 精英 | 精英带明显前摇/高血 |

- 清空全部波次 → 关卡完成 → **RAM +1（不超过上限）** → 弹出**增益三选一**。
- 单关目标时长 35–55 s（高性能前两盘允许 60–75 s，见 `50`）；最大同屏敌人 `min(30, 14 + 3×(d−1))`。
- 关卡标题显示路径：`C:\Users\DW\Documents\新建文件夹 (3)`，路径文案见 §8.4。

### 5.3 根目录 Boss 关

- 单 Boss + 周期召唤小怪；Boss 血条常驻顶部，50% 进入二阶段。
- 奖励：**传奇增益三选一（保底）** + **键帽 ×1（必掉）** + RAM 回满。
- 目标时长 45–75 s。

### 5.4 死亡与通关

- RAM 归零 → 若持有复活类增益（`交换分区` / `快照`，每局合计 1 次）则消耗并恢复；否则进入 **蓝屏（BSOD）** 页 → 结算。
- 击败本局最后一层磁盘的 Boss → **“计算机已安全关机”** 页 → 结算。
- 局内获得的键帽**立即入库，死亡不丢失**（ADR-004）。
- 失败也按表现结算碎片；通关额外 ×1.25 结算倍率。

## 7. Canon 数值与公式

> 所有取整规则：**四舍五入到整数**（`Math.round`），除非公式显式标注 `floor`。HP 可保留 1 位小数，显示时向上取整。

### 7.1 玩家基准

| 属性 | 值 | 说明 |
| --- | --- | --- |
| RAM（生命上限） | 5 | 整数；受伤扣整数 |
| 攻击力 | 10 / 发 | 单发基础伤害 |
| 攻击速度 | **攻击间隔 0.8 s/发** | 面板显示“1.25 发/s”（ADR-001） |
| 子弹速度 | 900 逻辑 px/s | 直线，朝准星方向 |
| 子弹半径 | 4 | 命中判定 |
| 初始弹数 | 1 | 无穿透 |
| 判定点半径 | 3 | 仅玩家光标中心参与受击判定 |
| 无敌时间 | 1.0 s | 受伤后闪烁 |
| 移动速度 | 320 逻辑 px/s | 8 向移动；无加速度、无冲刺 |
| 移动方式 | WASD/方向键（桌面）、左虚拟摇杆（移动） | 移动与瞄准分离（ADR-011） |
| 瞄准方式 | 鼠标位置 / 右虚拟摇杆 | 默认手动瞄准；准星与玩家分离 |
| 辅助瞄准 | 关闭（默认） | 开启后手动瞄准空闲 0.4 s 时软锁 480 px 内最近敌人；手动输入立即覆盖 |
| 每关回复 | +1 RAM | 文件夹通关时，不超上限 |
| Boss 通关回复 | 回满 RAM | 每层磁盘一次 |

- 玩家伤害成长来自：攻击力%、攻速%、额外弹数、穿透、暴击/特殊效果（由增益提供）。
- 玩家没有“蓝量/弹药”，字符弹无限；射速、弹数与穿透的硬上限见 `20 §1.4`。

### 7.2 敌人基准（节能 C 盘 = 1.0 倍）

| 属性 | 普通小怪 | 精英 | 根目录 Boss |
| --- | --- | --- | --- |
| 生命值 `HP0` | 30 | 90（3×） | 600 |
| 攻击力 `DMG0` | 1 | 2 | 2 |
| 攻击间隔 | 0.8 s | 1.4 s | 1.2 s（弹幕节拍） |
| 移动速度 | 60 px/s | 50 px/s | 40–70 px/s（分阶段） |
| 接触伤害 | 1（0.8 s/目标冷却） | 2 | 2 |
| 精英/Boss 特性 | — | 出场前摇 0.8 s、受击硬直更低 | 50% 血二阶段、召唤小怪 |

**行为原型（每种风格换皮，不换数值预算）**：

| 原型 | id | 行为 |
| --- | --- | --- |
| 弹窗 | `popup` | 追踪玩家，接触伤害 |

### 7.3 缩放公式（Canon，实现必须逐字对齐）

```ts
// d = 当前磁盘序号，C:=1, D:=2, E:=3, F:=4, G:=5
const K = (d: number) => 1 + 0.32 * (d - 1) + 0.08 * (d - 1) ** 2;

const D = { eco: 1.0, balanced: 1.3, performance: 1.6 } as const; // 节能/平衡/高性能
const M = (d: number, diff: keyof typeof D) => K(d) * D[diff];

// 敌人属性
enemyHp     = HP0 * M;
enemyDamage = normal: Math.min(2, 1 + Math.floor((M - 1) / 2.0));
              elite:  Math.min(3, 2 + Math.floor((M - 1) / 2.5));
              boss:   Math.min(4, 2 + Math.floor((M - 1) / 2.0));
enemySpeed  = 60 * Math.min(1.3, 1 + 0.05 * (d - 1));
enemyAtkSpd = Math.min(1.2, 1 + 0.04 * (d - 1)); // 攻击间隔 = 基准 / 该倍率
spawnCount  = Math.round(baseCount * (0.85 + 0.15 * M));
```

> `enemySpeed` 只作用于普通/精英（基准 60/50）；**Boss 不套用此式**，按 §7.2 的 40–70 分段移速实现（10 GC-01 裁决）。

**K / M 速查表**

| 磁盘 d | K | 节能 M | 平衡 M | 高性能 M |
| --- | --- | --- | --- | --- |
| 1（C:） | 1.00 | 1.00 | 1.30 | 1.60 |
| 2（D:） | 1.40 | 1.40 | 1.82 | 2.24 |
| 3（E:） | 1.96 | 1.96 | 2.55 | 3.14 |
| 4（F:） | 2.68 | — | 3.48 | 4.29 |
| 5（G:） | 3.56 | — | — | 5.70 |

**设计说明（ADR-002）**：HP 与刷新量吃满 `M`，**伤害不吃满**，用封顶离散曲线。原因是 `M` 最大 5.70，若伤害线性放大将出现“一碰即死”，违背弹幕游戏“靠走位而非血量”的核心体验；难度主要通过血量、数量、弹幕密度体现。

**示例复算（节能 C 盘）**：`M=1` → 小怪 HP 30、伤害 1、数量 ×1.00；与需求基准一致。
**示例复算（高性能 G 盘）**：`M=5.70` → 小怪 HP 171、伤害 2、数量 ×1.71；Boss HP 3418、伤害 4。

### 7.4 难度

| 难度 | id | 磁盘数 | D | 解锁条件 | 定位 |
| --- | --- | --- | --- | --- | --- |
| 节能 | `eco` | 3（C–E） | 1.00 | 默认 | 熟悉弹幕与增益，允许失误 |
| 平衡 | `balanced` | 4（C–F） | 1.30 | 通关节能 | 需要构建与走位 |
| 高性能 | `performance` | 5（C–G） | 1.60 | 通关平衡 | 极限密度，要求满配键盘 |

- 难度只通过 `D` 影响 `M`、结算倍率与磁盘数量；不改敌人行为脚本与关卡时长目标。
- 难度在 UI 中包装为电源计划：**节能 / 平衡 / 高性能**（见 `40`）。

### 7.5 磁盘与关卡系数

- 磁盘字母固定 `C: D: E: F: G:`，由难度截断。
- `C:` 固定 `style.system`；`D:` 起从 7 个可选风格中**不重复抽取**。
- 每通关一层磁盘，`d + 1`，`K` 按 §7.3 提升；同层内 5 个文件夹的 `K` 相同。
- 层间过场：显示 `磁盘 D: 已挂载` → 风格揭晓 → 回满 RAM → 继续。

### 7.6 增益（Buff）

| 项 | 规则 |
| --- | --- |
| 触发 | 每个文件夹通关 1 次；每层磁盘 Boss 通关 1 次 |
| 形式 | 暂停并弹出 3 张卡，选 1；Boss 关为 3 张**传奇**卡（不足 3 张时以稀有补足，详见 `20 §1.2`） |
| 稀有度 | 普通 / 稀有 / 传奇，权重 **6 : 3 : 1**（60% / 30% / 10%） |
| 保底 | Boss 必出传奇（3 选 1）；传奇池满则改为 3 张稀有卡 + 50 碎片 |
| 池容量 | 普通 12 / 稀有 10 / 传奇 8，共 **30** 个（详见 `20`） |
| 叠层 | 普通最多 3 层、稀有最多 2 层、传奇 1 层（特例在 `20` 标注） |
| 重随 | 默认不可重随；键帽套装可提供每局 1 次免费重随 |
| 强度预算 | 普通≈等效输出 +6%；稀有≈+10% 或机制；传奇≈+18% 或规则级效果（详见 `50`） |

**Canon 示例（来自需求）**：
`交换分区 buff.swap_partition`（传奇，1 层）：RAM 归零时消耗此增益，立即以 100% RAM 复活，并获得 1.5 s 无敌。每局最多触发 1 次。

### 7.7 键帽与局外成长

**87 键键盘 Canon 布局（7 行，共 87 键）**

**键帽稀有度与属性**

| 稀有度 | 数量 | 属性点/键 | 重复转碎片 | 说明 |
| --- | --- | --- | --- | --- |
| 普通 | 60 | 1 | 20 | 少量属性 |
| 稀有 | 24 | 2 | 60 | 中量属性，部分带套装 |
| 传奇 | 3（Esc/Enter/Space） | 4 | 250 | 大属性 + 套装核心 |

- 1 属性点 = `攻击 +0.20%` 或 `攻速 +0.12%` 或 `移速 +0.15%`（每键固定一种，见 `20`）。
- 属性软上限（防爆炸）：`eff = cap × (1 − e^(−raw/cap))`；攻击 cap 18%、攻速 cap 12%、移速 cap 10%。
- 套装（详见 `20`）：WASD（移速 +3%）、方向键（无敌 +0.1 s）、F1–F4（每局 1 次免费重随）、主键区 8 键（攻击 +2%）、Esc+Enter+Space（增益选择 4 选 1）、全 87 键（攻击 +1%、移速 +3%）。
- **局内获取**：文件夹通关 2% 概率掉键帽；Boss 100% 掉键帽（稀有度 50/40/10）。获得即入库，死亡保留。
- **抽取**：单抽 200 碎片，十连 1800；概率 普通 70% / 稀有 25% / 传奇 5%；十连保底稀有；50 抽无传奇则下一抽保底传奇。
- 键帽对局外只提供属性与套装，不提供局内货币/掉落加成（避免滚雪球）。

### 7.8 碎片经济（Canon）

```
raw  = 0.5 × 击杀数 + 8 × 通关文件夹数 + 30 × 击杀 Boss 数 + 50 × 通关磁盘数
mult = D × (1 + 0.05 × min(无伤文件夹数, 5)) × (通关 ? 1.25 : 1.0)
碎片 = floor(raw × mult)
```

- “无伤文件夹”= 该文件夹关内未损失 RAM。
- 节能满通关（约 385 击杀 / 15 文件夹 / 3 Boss / 3 磁盘，5 个无伤）≈ **863 碎片** ≈ 4.3 抽。
- 平衡满通关 ≈ 1,523 碎片 ≈ 7.6 抽；高性能满通关 ≈ 2,412 碎片 ≈ 12.1 抽。
- 目标：**一局 ≈ 3–5 抽（节能），高性能 ≈ 12–15 抽**；纯碎片集齐 87 键约 8–23 局（不含局内掉落与重复补偿）。
- 首次通关难度额外奖励：节能 200 / 平衡 400 / 高性能 800 碎片（一次性，记录于存档）。
- 不设碎片上限；不卖碎片、无内购。

### 7.9 随机与种子

- 全局使用可复现的 32-bit 种子 RNG（`mulberry32`），局种子在暂停页与结算页展示。
- 抽取顺序固定：磁盘风格 → 关卡波次编成 → 增益候选 → 掉落；同种子同操作可复现（用于测试与 bug 复现）。

### 10.2 图形语言

- **敌人 = 软件图标**：圆角方形磁贴 + 图标字形 + 1px 内描边 + 轻微投影；受击闪白、死亡碎裂为像素块。
- **玩家 = 玩家光标 + 瞄准准星**：光标为经典箭头（WASD/左摇杆移动），准星为十字/圆环（鼠标/右摇杆），两者分离；判定点仅光标中心 3 px。移动端横屏时左下/右下显示虚拟摇杆。
- **子弹 = 字符**：一串 2–6 个等宽字符（`0101`、`0xFF`、`sudo`、`rm`、`<div>`…），沿射击方向轻微拉长；命中时字符散开消失。
- UI 动效 80–200 ms，击杀/阶段/结算等演出 ≤ 600 ms；屏幕震动默认开启、可关；无高频闪烁（≤ 3 Hz）。

### 10.4 音频

- 全部合成：UI 点击、键盘敲击、字符弹发射（不同字符音高不同）、命中、死亡、错误提示音、增益安装、Boss 警报、蓝屏和弦、关机下行音。

- 总线：`source → gain → compressor → destination`；同时发声 ≤ 16；提供音乐/音效独立开关。

### 10.5 图标与许可合规（Canon）

- DesktopWar 为**开源、非商业发行**项目；图标版权归各集合作者，按集合许可使用。
- 仅允许：`logos` / `simple-icons`（CC0-1.0）、`devicon`（MIT）、`mdi` / `carbon`（Apache-2.0）；均允许商业使用；其他集合（含 CC BY-NC/SA、GPL）构建失败。
- 品牌名称与 logo 为各自商标：仅作桌面软件的描述性/戏仿识别，不暗示赞助或背书；发行物料不使用品牌 logo。

### 10.6 本地化（i18n）预留

- **语言范围**：`zh-CN` 为默认与唯一发布语言；`en-US` 只预留目录与类型，不随 v1 发布。存档 `settings.language` 取 `'zh-CN' | 'en-US'`，缺失/未知/未发布回落 `zh-CN`。
- **文案单一来源**：界面、风格/敌人/Boss/增益/键帽名称、路径池、蓝屏/关机/更新/暂停/结算文案全部走 `src/i18n/locales/<locale>.ts` 的 `MessageKey`；数据表只存 id，不存展示文案。
- **固定文案**：可翻译，但 `:(`、`DESKTOP_WAR_RAM_EXHAUSTED`、`desktopwar.exe`、百分比与段落结构是 token，任何语言不得改写。
- **字体与排版**：只打包 ASCII 像素字体；CJK 走系统字体栈。布局按源文案预留 1.4× 宽度，按钮可换行，固定文案不截断。
- **数字/时间**：Canon 格式不随语言变化（`1,240`、`mm:ss`、24h `HH:mm`、`0x` + 8 位大写）；v1 固定 `dir="ltr"`，不做 RTL。
- **非目标**：不在运行时联网拉取翻译、不引第三方 i18n 库、不做语言包热更新；切换语言立即生效且不重开局。

## 13. 架构决策记录（ADR）

| id | 决策 | 理由 |
| --- | --- | --- |
| ADR-001 | “攻击速度 0.8”解释为**攻击间隔 0.8 s/发**，UI 显示 1.25 发/s | 若按 0.8 发/s，则 30 HP 小怪需 3.75 s 击杀，与弹幕节奏冲突；间隔制更符合手感与需求基准 |
| ADR-002 | 敌人伤害用封顶离散曲线，HP/数量吃满 `M` | 避免高难度一击必杀；难度靠密度与血量，见 §7.3 |
| ADR-003 | 风格只影响美术与怪种 | 保证“抽到喜欢的风格”不改变难度预期，也便于内容扩展 |
| ADR-004 | 局内键帽获得即入库、死亡保留 | 降低挫败；键帽是长期收集，不应成为风险投资 |
| ADR-005 | Iconify 图标构建期下载、图集化、内联进产物 | 运行时零网络，加载可控，规避第三方 CDN 波动 |
| ADR-006 | Canvas 2D + DOM UI，无框架、无引擎 | 轻量、可控、包体小；UI 用原生 DOM 足够 |
| ADR-007 | 自动开火，无射击键 | 保留自动射击的爽感；把操作复杂度留给走位、瞄准与选增益 |
| ADR-008 | 局外只给属性与套装，不给局内经济加成 | 防止滚雪球，保持局内构建为核心乐趣 |
| ADR-009 | 单一逻辑分辨率 1280×720 横屏 | 桌面与移动横屏共用一套战场与刷怪锚点；移动端只做安全区适配 |
| ADR-010 | 所有随机走种子 RNG | 可复现、可测试、可复现 bug |
| ADR-011 | 移动与瞄准分离（WASD/左摇杆移动，鼠标/右摇杆瞄准）；「自动锁定最近目标」默认关闭 | 避免自动索敌“抢手”；默认手动瞄准保留操作上限，辅助瞄准仅作为可选设置 |
| ADR-012 | 敌人/Boss 磁贴使用真实软件品牌图标（`logos`/`simple-icons`/`devicon`），缺失回退 `mdi`/`carbon` | 强化“桌面即战场”隐喻与辨识度；许可白名单见 §10.5，商标风险见 `40 §4.2` |
| ADR-013 | 预留 i18n：zh-CN 默认、en-US 预留；文案键化（`src/i18n`），数据表只存 id；固定文案 token 不翻译 | 后续加语言不改玩法/数据；避免文案散落与运行时依赖 |

## 14. 验收总则

1. **一致性**：`10/20/30/40/50/60` 中的所有数值、命名、id 必须能在本文找到依据；冲突即为缺陷。
2. **可实现性**：一个熟悉 TS/Canvas 的开发者仅凭 `00 + 30` 能在 1 天内跑通“移动 + 射击 + 一个敌人 + 受击 + 死亡蓝屏”。
3. **可测性**：§7 公式均可写成纯函数并单测；`50` 提供 TTK/经济的期望区间与校验脚本设计。
4. **预算**：§9 的体积/性能指标进入 CI 检查（M1 起）。
5. **文案**：蓝屏、关机、增益窗口文案在 zh-CN 不得改写；其他语言按 §10.6 翻译且 token 不变。
