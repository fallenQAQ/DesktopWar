## 1. 技术选型与权衡

### 1.1 选型决策表

| 领域 | 选择 | 被否方案 | 否掉的理由 |
| --- | --- | --- | --- |
| 语言/构建 | TypeScript 5.x `strict`（`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`）+ Vite 7.x + npm，`build.target: 'es2022'` | JS / 非严格 TS、webpack | 数据表、id 引用、公式必须编译期可查；零配置 HMR |

| 架构 | 自研 SoA ECS（`src/ecs/world.ts`） | bitecs / ecsy / 通用 ECS | 通用查询开销与“30 敌”规模不匹配 |

| 测试 | Vitest（当前单元） + 计划中的无头仿真/E2E | Jest / Cypress | 与 Vite 同源、启动快 |

### 1.2 “零运行时依赖”的可执行定义

`dependencies: {}`（保持为空，新增即评审）；devDependencies 当前仅 `typescript ~5.9`、`vite ^7.1`、`vitest ^3.2`、`@types/node`。图标光栅化（`@resvg/resvg-js`、`sharp`、`svgo`）、`tsx`、Playwright 等属于 §9 计划管线，接入前不安装。CI 另查：`dist/**/*.js` 不得有外部 `import`；产物不得含 `http(s)://` 外部主机名（许可文本除外）。

不用引擎/框架/workbox：自写循环、碰撞、渲染排序、DOM 局部更新、SW 缓存版本 → 换取零第三方运行时与 ~40KB 体积。图集 WebP + PNG 回退（多一份 PNG）；字形图集运行时烘焙（首次进战斗多 ~3–6ms，省 30–60KB 首屏）。

## 3. 轻量 ECS

### 3.1 设计边界

只做三件事：**定长实体、SoA 组件、显式系统顺序**。不做：archetype 原型、动态组件增删、整 World 序列化、事件驱动隐式调度。为“同屏 400+ 实体、零 GC”牺牲通用性换确定性。

### 3.2 实体与上限

```ts
export type Entity = number;             // index(10bit) | generation(22bit)，永不为 0
export const MAX_ENTITIES = 1024;
export const enum Kind { Player = 1, Enemy, PlayerBullet, EnemyBullet, Pickup, Fx }
export const LIMITS = { enemies: 32, playerBullets: 160, enemyBullets: 320, pickups: 32, fx: 256 } as const;
// 30/120/240 是玩法上限（00 §9），池留 Boss 召唤与余量；合计 ≤1024
```

`generation` 让“已死实体的旧引用”自动失效；池满时 `spawn` 返回 `0`，调用方必须处理（例：掉落物不再生成，而非删掉别的实体），并计入 metric，不崩溃。

### 3.3 SoA 组件布局（字段缩写示意）

```ts
// 全字段定长 typed array，boot 一次分配约 200KB，永不扩容
interface Components {
  x y px py vx vy r hp maxHp life: Float32Array;      // px/py 为上一步值（插值用）；r 玩家=3
  team kind tint eProto eTier bPierce bGlyph ram: Uint8Array;   // team 0 中立/1 玩家/2 敌；tint 调色板
  flags buffMask: Uint32Array;                        // flags：1 存活 2 可碰撞 4 穿透 8 闪烁
  sprite: Uint16Array;                                // 图集帧 id（atlas registry 分配）
  bGlyph: Uint8Array;                                 // 预生成 2–6 字符字符串表索引（不逐帧拼串）
  bDamage eAiTimer eAtkCd eHitCd invuln fireCd: Float32Array;   // eTier 0 普通/1 精英/2 Boss
}
```

热点组件用定长数组；冷组件（Boss 阶段、掉落表、增益实例）用 `Map<Entity, T>`——常数级且不需逐帧扫描。

### 3.4 World 接口骨架（ECS 核心接口）

```ts
export interface StepCtx { readonly dt: 1 / 60; readonly step: number; readonly rng: Rng;
  readonly input: Intent; readonly events: EventQueue; readonly run: RunState; }
export interface World { readonly c: Components; readonly enemies: Int32Array;   // 稠密列表 + len
  readonly playerBullets: Int32Array; readonly enemyBullets: Int32Array; readonly pickups: Int32Array;
  spawn(kind: Kind): Entity;          // 返回 0 表示池满
  despawn(e: Entity): void;           // swap-remove + generation++
  isAlive(e: Entity): boolean; player(): Entity; tick(ctx: StepCtx): void; }
export type System = (w: World, ctx: StepCtx) => void;
```

### 3.5 对象池与查询

- 实体池：`freeList: Int32Array(1024)` + `freeTop`；`despawn` 压回 freeList，同时从所属 Kind 列表 swap-remove。
- 列表 swap 会打乱顺序，但**只要 spawn/despawn 序列确定结果就确定**；需顺序稳定处（渲染遮挡）用 `spawnSeq` 排序键。
- “查询”不是泛型 join：系统直接遍历对应 Kind 稠密数组；跨表查询只有三种（弹×敌、敌弹×玩家、敌×玩家），全部经空间哈希（§6）。
- 热路径禁令：`filter/map`、对象字面量、闭包、字符串拼接、`Map` 查找；遍历写 `for (let i = 0; i < n; i++) { const e = list[i]!; … }`。
- 确定性：禁 `Math.random`、`Date.now`（UI 展示除外）、`Set/Map` 迭代顺序依赖、`Object.keys` 顺序依赖；浮点只做加减乘与 `sqrt`。

### 3.6 系统调度顺序（固定步内）

系统顺序以 `10 §1.3` 的 1–18 为准；本文只插入三个技术步骤：`0 snapshotPrev`（x,y→px,py）、`10.5 hashRebuild`（敌人空间哈希，cell=64）、`17.5 fxUpdate`（粒子/字符散开/震动衰减）。`eventsFlush` 恒为最后一步；不得改变 10 的相对顺序（`10 §13.3`）。

> 理由：先移动后碰撞、生成在移动前、副作用最后；音频/UI 不影响逻辑，仿真可关闭表现。

## 4. 游戏循环

### 4.1 accumulator + 插值

```ts
export const FIXED_DT = 1 / 60;
export function startLoop(step: (dt: number) => void, render: (a: number) => void) {
  let acc = 0, last = performance.now();
  const frame = (now: number) => {
    requestAnimationFrame(frame);
    const dt = (now - last) / 1000; last = now;
    acc += Math.min(dt, 0.25);                 // 切后台回来不补 10 秒；暂停时 acc=0、last 重置
    let n = 0;
    while (acc >= FIXED_DT && n < 3) { step(FIXED_DT); acc -= FIXED_DT; n++; }
    if (acc >= FIXED_DT) acc = 0;              // 仍有积压 → 丢弃，防死亡螺旋
    render(acc / FIXED_DT);                    // alpha ∈ [0,1)
  };
  requestAnimationFrame(frame);
}
```

- 逻辑永远 `1/60`；`timeScale` 只做慢动作/顿帧（hitstop 60–90ms 用 0.15 倍），**不改变步长**。
- 渲染每帧最多 1 次，逻辑可能 0 次（高刷屏）——插值保证 120Hz 屏平滑；暂停 `paused=true` + 清 accumulator + `audio.suspend()`，恢复时重置 `last`。
- 失焦/切后台：`visibilitychange`/`blur` 自动暂停（移动端切后台必触发）；`pagehide` 立即 flush 存档。

### 4.2 时间相关约定

| 项 | 约定 |
| --- | --- |
| 所有计时 | 秒（float），按固定步累加，不用 `Date.now` |
| 攻击间隔 | 0.8 s/发（ADR-001），`fireCd -= dt` 判定，不用 `setInterval` |
| 无敌 | 1.0 s；受击 `invuln = 1.0`，闪烁 `Math.floor(t * 4) % 2`（2.0 Hz） |
| 接触伤害冷却 | 0.8 s/目标（00 §7.2），存于 `eHitCd` |
| 波次间隔 | 数据表定义（`10`），spawner 用剩余秒计数 |
| 出生位置 | 追击型从屏幕外环进入；定点/绕行型必须落在可视安全区（`10 §5.6`、00 ADR-014） |
| 随机 | 只在 step 内消费（00 §7.9 RNG），渲染/UI 不消费 |

## 5. 渲染管线

### 5.1 图层（刻意只有 3 层）

```text
 DOM 覆盖层 #ui       HUD、暂停、增益三选一、结算（原生 DOM，pointer-events 按需）
──────────────────────────────────────────────────────────────
 Canvas #world       世界、敌人、子弹、特效（每帧清屏 + 重绘）
──────────────────────────────────────────────────────────────
 离屏 canvas bgCache 壁纸渐变 + 桌面网格 + 任务栏暗示（boot 画一次，每帧 1 次 drawImage）
```

- 主画布 `getContext('2d', { alpha: false, desynchronized: true })`；背景不透明可省一次合成。
- 不用多层 Canvas（每层一次合成，移动端代价明显）；“屏幕震动”只对 `#world`/`#ui` 做 CSS `transform`。所有坐标 = 逻辑坐标，适配靠 CSS `transform: scale()`，不改逻辑分辨率。

### 5.2 视口与横屏安全区

```ts
export type Orientation = 'landscape' | 'portrait';   // 仅用于旋转提示，不是游戏视口
export interface Viewport {
  readonly w: 1280; readonly h: 720;  // 唯一逻辑分辨率（横屏），移动端只做安全区适配
  readonly dpr: number;               // min(devicePixelRatio, 2)
  readonly renderScale: number;       // 1 | 0.75（动态降级，§15.3）
  readonly cssScale: number;          // min(vw/w, vh/h)，居中 letterbox
  readonly orientation: Orientation;  // portrait 时只叠加旋转覆盖层，不切战场
  readonly safe: { top: number; bottom: number; left: number; right: number };  // 56/48/24 逻辑 px
}
export function computeViewport(cssW: number, cssH: number, dpr: number, orientation: Orientation): Viewport;
// w/h 恒为 1280×720；orientation 仅决定是否叠加旋转覆盖层
```

| 项 | 规则 |
| --- | --- |
| backing store | `w × dpr × renderScale`，`ctx.setTransform(dpr*renderScale,0,0,dpr*renderScale,0,0)` |
| CSS 尺寸 | `w × h` 逻辑像素经 `cssScale` 缩放；`image-rendering: pixelated` 仅用于像素字体层 |
| 安全区 | 横屏固定上 56（Boss 血条）/ 下 48（拇指与摇杆）/ 侧 24；与 `env(safe-area-inset-*)` 取较大值（换算为逻辑 px）；刷怪、HUD 与装饰只在安全区内布局 |
| 旋转/尺寸变化 | `ResizeObserver` 防抖 100ms → 重算 viewport；切竖屏不重建战场，只叠加旋转覆盖层并暂停，回横屏后沿用同一 viewport 继续 |
| `alpha:false` | 背景缓存必须铺满，否则黑边出现在错误位置 |

> Canon 引用：00 §3、§9、§12（TBD-01）、ADR-009。移动端仅横屏：竖屏 = 旋转覆盖层（DOM，不是游戏视口），不缩放、不重排、不创建第二套逻辑坐标。

### 5.3 字符弹渲染：预烘焙字形图集

> **当前状态（v0.2.1）**：字符弹直接 `fillText` 系统等宽字体；预烘焙字形图集为 M5 剩余工作。以下为目标方案，接入前不改变逻辑判定。

**问题**：每帧最多 360 颗子弹 × 2–6 字符，`fillText` 在 Canvas2D 上是重路径（字形整形、字体回退），且字体加载造成首帧抖动。
**方案**：ASCII 95 字符（`0x20–0x7E`）在 boot 时**一次性**烘焙到离屏画布，转 `ImageBitmap`；热路径只用 `drawImage` 取子矩形。

```ts
export interface GlyphAtlas {
  readonly bitmap: ImageBitmap;   // 10×10 网格，cell = 2×字号
  readonly cell: number;          // 烘焙像素尺寸（2x）
  readonly cols: number;
  draw(ctx: CanvasRenderingContext2D, ch: number, x: number, y: number,
       scale: number, rot: number, tint: Tint): void;   // 白色字形；染色见下表
}
export async function bakeGlyphAtlas(fontFamily: string, fontPx: number): Promise<GlyphAtlas>;
```

| 决策 | 做法 | 理由 |
| --- | --- | --- |
| 烘焙时机 | `document.fonts.load()` 完成后、进入战斗前 | 避免 `fillText` 用回退字体造成字形错位 |
| 字号/格 | 字号 20 逻辑 px，cell 40×40（2x），10×10=95 格 | 子弹字符视觉 2–6 字，缩放到 0.8–1.15 |
| 染色 | 烘焙 2 套：白（普通）、危险红（精英/Boss 弹）；其余颜色用 `globalAlpha` | 图集内存 3.2MB→1.6MB；热路径无合成操作 |
| 拉伸 | 沿飞行方向 `scaleX = 1 + 0.25 * (speed/900)`，用 `setTransform` | 00 §10.2“沿飞行方向轻微拉长” |
| 像素对齐 | 位置 `Math.round(x * dpr) / dpr` | 避免半像素模糊 |
| 回退 | 字体加载超时 1.5s → 系统 `monospace` 烘焙并继续 | 不阻塞开局 |

### 5.4 敌人图标与图集（计划）

- 当前：`src/render/renderer.ts` 以软件名首字母/简称绘制程序化磁贴，不加载图集。
- 目标：§9 构建 `atlas/<style>.webp` + `.png` 回退 + `<style>.json`；运行时 `createImageBitmap`，帧 `{x,y,w,h}` 走 `drawImage`。
- 每个图标烘焙 `normal` + `silhouette` 两帧，受击闪白直接切帧；磁贴圆角/描边/投影预烘焙进帧内；Boss 图标 128 逻辑 px（2x=256）。

### 5.5 批处理与绘制预算

| 图层 | 每帧 drawImage 上限 | 状态切换原则 |
| --- | --- | --- |
| 背景 | 1 | — |
| 装饰 | 12 | 与敌人共用图集，按帧 id 升序排 |
| 敌人 | 30 (+30 血条) | 血条只在受击/精英显示，普通怪不画 |
| 玩家弹 | 120 × 2.2 字符 ≈ 264 | 同图集 + 同 tint 连续绘制 |
| 敌弹 | 240 | 小三角/短字符，单 tint |
| 特效 | 256（粒子合并为 1 次 `fillRect` 批） | 粒子用同色批次，避免逐粒子换色 |
| 玩家 | 2 | 光标 + 残影 |
| **合计** | **≈900 drawImage/帧**（P95 < 2.5ms） | 图内按 `atlasId → frameId → tint` 插入排序，不做通用渲染队列 |

### 5.6 摄像机

世界即逻辑坐标，**无缩放、无跟随**（桌面就是战场，边界 = 屏幕边界）。仅两点：① 屏幕震动 `shakeX/Y` 衰减（80ms）叠加到 `ctx.translate`，用整数像素避免模糊；② 移动端横屏沿用同一逻辑刷怪边界（`10 §5.6`），安全区只约束 HUD 与触控，不缩放战场，避免刷怪锚点与逻辑坐标漂移。

## 6. 碰撞与空间划分

### 6.1 模型

全部是圆 vs 圆，无旋转盒、无物理引擎（00 §11 非目标）。

| 对 | 频率 | 判定半径 | 处理 |
| --- | --- | --- | --- |
| 玩家弹 × 敌人 | 每步 | `4 + enemy.r`（子弹 4，00 §7.1） | 伤害、`bPierce--`，0 则回收 |
| 敌弹 × 玩家 | 每步 | `bullet.r + 3`（玩家判定 3，00 §7.1） | 按 `enemyDamage` 扣 RAM（1–4），无敌 1s，清弹（可选增益） |
| 敌人 × 玩家 | 每步 | `enemy.r + 3` | 接触伤害 + 0.8s/目标冷却 |
| 拾取 × 玩家 | 每步 | `10 + 8`（吸附半径） | 拾取 |

玩家判定点**只有 3px**（00 §7.1），视觉光标不放大：这是弹幕手感核心，渲染与碰撞解耦。

### 6.2 空间划分（当前直接遍历）

- 当前实现：同屏敌人 ≤32，玩家弹/敌弹对敌人直接遍历距离判定；无空间哈希、无额外分配。
- 目标优化（计划）：`cell = 64` 的空间哈希只重建敌人，子弹查 3×3 邻域；在性能门禁显示需要时再接入，不提前增加复杂度。
- 出界裁剪：子弹离开 `[-64, w+64] × [-64, h+64]` 立即回收；敌人不裁剪（Boss 战有场外入场）。

### 6.3 命中事件与去重

- 命中**立即扣血**（同 step 内顺序确定），但音效/飘字/震动进入 `EventQueue`，step 14 统一派发 → 逻辑与表现解耦，仿真可关闭表现。
- 一颗子弹对同一敌人只结算一次：命中后 `bPierce--`，穿透 0 立即 `despawn`；多段伤害（激光类增益）走“每 N 秒一次”计时器，不靠重叠去重。
- 玩家受击：`invuln > 0` 直接跳过且不产生事件 → 1.0s 无敌是**逻辑**而非表现。

### 6.4 性能预算（最坏同屏：30 敌 / 120 玩家弹 / 240 敌弹）

| 计算 | 次数/步 | 预算 |
| --- | --- | --- |
| 敌人哈希重建 | 30 | < 20µs |
| 玩家弹 × 邻域 | 120 × ~6 候选 | < 60µs |
| 敌弹 × 玩家 | 240 距离判定（可先用 3×3 桶筛到 ~10） | < 30µs |
| 敌人 × 玩家 | 30 | < 5µs |
| 掉落/拾取 | 32 | < 5µs |
| **碰撞合计** | — | **< 150µs/步** |

离散检测可行性：子弹 900px/s ÷ 60 = **15px/步**；最小敌人半径 12 → 单步位移小于直径，不会隧穿；Boss 召唤小怪半径 ≥12 同理。若后续出现 >1200px/s 的弹，改为线段-圆 sweep（预留 `sweepCapsule`，v1 不启用）。

## 7. 输入

### 7.1 统一模型（move_intent / aim_intent）

```ts
// src/input/input.ts —— 输入层唯一出口；pointer/keyboard/touch 都归一到 Intent
export type Vec2 = { readonly x: number; readonly y: number };   // 归一化方向，长度 0–1
export interface Intent {
  readonly move: Vec2;    // move_intent：WASD/方向键（8 向）或 左摇杆；320 px/s
  readonly aim: Vec2;     // aim_intent：鼠标相对玩家 或 右摇杆；零向量 = 保持上次方向
  readonly aimActive: boolean;   // 本帧是否有手动瞄准输入（自动锁定只在 false 时介入）
  readonly aimMode: 'pointer' | 'stick' | 'auto';   // auto 仅来自自动锁定
  readonly autoLock: boolean;   // 存档 settings.autoLock 快照，默认 false
  readonly paused: boolean;      // 本步是否请求暂停
  readonly primary: boolean;     // 手势解锁音频/点击 UI 的语义位
  readonly keys: number;         // WASD/方向键位掩码，仅桌面
}
```

| 平台 | `move_intent` | `aim_intent` |
| --- | --- | --- |
| 桌面键盘 | `WASD`/方向键 → 8 向单位向量；320 逻辑 px/s，无加速度（00 §3） | — |
| 桌面鼠标 | — | `pointer − player` 归一化；距玩家 <24px 时保持上次方向；鼠标绝对位置只服务准星与 UI |
| 移动左摇杆 | 左下浮动摇杆：首次触点为圆心，位移/48px 得力度，死区 8px | — |
| 移动右摇杆 | — | 右下浮动摇杆：方向即射击角度，参数同上；左右摇杆可同时按住 |
| 自动开火 | 恒开，无射击键（ADR-007）；射速固定，朝向只由 `aim_intent` 决定 | 同左 |
| 自动锁定 | 默认关闭 | 开启后仅手动瞄准空闲 0.4s，以 360°/s 软锁 480px 内最近敌人；任何手动瞄准输入立即覆盖（ADR-011） |
| 暂停 | `Esc` / 右上角按钮；`visibilitychange`/`blur` 自动暂停并清空 intent | 同左 |
| 失焦/取消 | `blur`/`visibilitychange:hidden`/`pointercancel` 清空 move/aim 并释放触点 | 同左 |

- 触摸分区：以 1280/2 为界，左半屏只认移动摇杆、右半屏只认瞄准摇杆；每区最多 1 个 `pointerId`，其余忽略（防误触）。
- 摇杆绘制：浮动原点 + 96px 底盘（半径 48）+ 44px 摇杆头 + 8px 死区；触点消失立即归零，不保留“粘滞”方向。
- **光标与准星分离**：`move` 驱动玩家光标（受击判定仅其中心 3px，§6.1），`aim` 只驱动射击方向与准星；自动锁定不改光标位置。
- 自动锁定读取存档 `settings.autoLock`（默认 false）；暂停页修改后下一逻辑步生效，不写其他局内状态。

### 7.2 页面级手势与方向处理

- CSS：`html, body { touch-action: none; overscroll-behavior: none; user-select: none; -webkit-tap-highlight-color: transparent }`。
- 阻止 `contextmenu`、`gesturestart/change`、`dblclick` 缩放；`<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,viewport-fit=cover">`。
- 取舍：`maximum-scale=1` 牺牲可访问性缩放，换“误双击不缩放/不位移”——弹幕游戏可接受，记录于 `40` 的 UX 说明。
- 竖屏：`orientation`/`resize` 判定 portrait → 显示旋转覆盖层、`paused = true`、清空 intent；恢复横屏后保持暂停，由玩家点“继续”。
- 全屏方向锁定（`screen.orientation.lock('landscape')`）为计划项；当前只依赖 manifest + 旋转覆盖层，不阻塞开局。
- `pointercancel` 必须当 `pointerup` 处理并清空对应摇杆；首次 `pointerdown`/`keydown` 调 `audio.unlock()`，同时用于隐藏“点击开始”。

### 7.3 首帧与输入延迟

| 指标 | 保持值 / 做法 |
| --- | --- |
| 首次可操作（4G） | ≤2.5s（00 §9，不变）；boot 先挂输入监听再载图集，首帧即可采样 |
| 输入生效 | 事件当帧写入 Intent，下一逻辑步消费；不做平滑/加速度，不额外加帧 |
| 离散 UI 输入 | 按钮点击 200ms 门控（跨重渲染）；`Esc` 忽略 auto-repeat；滑杆设置写入 500ms 去抖，`pagehide`/`visibilitychange:hidden` 立即 flush |
| 连续输入 | 移动/瞄准不额外去抖，保持每逻辑帧采样 |
| 首帧渲染 | 字体/图集未就绪时按 §5.3 回退与 R8 处理，不阻塞输入 |

## 8. 音频

### 8.1 图形与总线

```text
Oscillator/Noise → ADSR(Gain) ─┬─► musicBus(Gain .55) ─┐
                               └─► sfxBus(Gain .8) ────┴─► master(.8) ─► Compressor ─► destination
```

- `AudioContext` 惰性创建（首次手势），`latencyHint: 'interactive'`；`suspend/resume` 跟随暂停。
- 压缩器：`threshold -18dB / knee 6 / ratio 4 / attack 0.003 / release 0.25`，防 16 声部叠加削波。
- **不使用** `AudioWorklet`、不加载任何音频文件、不用第三方音频库。

### 8.2 合成器

```ts
export interface Envelope { a: number; d: number; s: number; r: number; }   // 秒 / 0–1
export interface ToneSpec {
  wave: OscillatorType;               // 'square' | 'sawtooth' | 'triangle' | 'sine'
  freq: number; freqEnd?: number;     // 频率滑音（死亡下行音）
  env: Envelope; filter?: { type: BiquadFilterType; freq: number; q: number }; gain: number;
}
export interface NoiseSpec { duration: number; filter: { type: BiquadFilterType; freq: number; q: number }; gain: number; }
```

| 音效 id | 合成配方（终值由 `40` 音效清单定稿） |
| --- | --- |
| `sfx.fire` | square 440/554、triangle 659、saw 880（按字符组，40 §5.2）；字符 hash ±6% 音高 |
| `sfx.hit` | noise 40ms + bandpass 2kHz Q 1.2，gain 0.18 |
| `sfx.enemyDie` | sawtooth 300→80Hz 250ms，gain 0.2 + 短噪声 |
| `sfx.playerHurt` | square 220Hz 120ms + 噪声爆，gain 0.35 |
| `sfx.buffInstall` | 三音上行（523/659/784），每音 60ms |
| `sfx.bossAlarm` | 双音交替 440/330，8 次，120ms 间隔 |
| `sfx.bsod` | 3 正弦（110/164.8/220）2.2s 长衰减 + 低通 |
| `sfx.shutdown` | 正弦 660→110 下行 1.2s |

- 噪声用 boot 时预生成的 1s 白噪声 `AudioBuffer` 复用，不每帧 `createBuffer`。
- 声部上限 **16**（00 §10.4）：`activeVoices` 计数；满时抢占“进度 >70% 且增益低”的声部；UI 音效保留 4 个专用槽位。

### 8.3 调度

```ts
export interface MusicPattern { bpm: number; steps: number; tracks: PatternTrack[]; }
export interface PatternTrack { wave: OscillatorType; notes: (number | 0)[]; gain: number; env: Envelope; }
// SFX：立即（下一音频量化点 0–3ms），不等 lookahead
// 音乐：25ms 定时 tick（self-correcting），提前 100ms 排 BPM 网格上的音符
```

- 音乐 2 轨（菜单 96 BPM / 战斗 128 BPM，00 §10.4）；战斗 16 分音符网格（每步 117.2ms）；Boss 战为战斗轨变奏（低八度根音 + 噪声底鼓），小节边界切换。
- 暂停 `ctx.suspend()`，恢复 `ctx.resume()` 并重排后续音符（丢弃过期音符，不补播）；静音设置持久化到 `meta/settings`，音乐/音效独立 0–1。
- 音量包络全部用 `setValueAtTime`/`linearRampToValueAtTime` 预排，不逐帧写参数。

## 9. Iconify 资产管线（计划，当前未接入）

> 目标：**构建期把图标变成图集，运行期零网络、零 SVG 解析**（00 ADR-005）。
> **当前状态（v0.2.1）**：未打包任何第三方图标；`src/render/renderer.ts` 绘制程序化首字母磁贴（`40 §4.5` L3）。本节是接入前的执行方案，不描述现有产物。

### 9.1 事实与硬规则

- 渲染端点：`https://api.iconify.design/{prefix}/{name}.svg`；批量：`/{prefix}.json?icons=a,b,c`；元数据：`/collections?prefix=…`（license/version）。
- 光栅化：`@resvg/resvg-js` → PNG，`sharp` 编码 WebP；SVG 原始文件提交入库，CI 离线构建。
- **硬规则**：① 只在构建期访问网络；② 每个图标有 license 记录；③ 敌人/Boss 优先 `logos`/`simple-icons`/`devicon`，`mdi`/`carbon` 只作 UI 与缺图回退；④ 仅允许 CC0-1.0 / MIT / Apache-2.0，其他集合构建失败。
- 许可白名单与商标说明见 `00 §10.5`、`40 §4.2`。

### 9.2 manifest 与派生规则（计划）

唯一事实来源：`assets/icons/manifest.ts`（TS，编译期可校验）。每条记录至少包含 `id`、`atlas`、`use`、`size`、`paint`、`silhouette`、`fallback`。

```ts
export type IconId = `${string}:${string}`;                    // 'mdi:folder'
export type AtlasId = 'core' | StyleId;                        // 按风格拆图集
export const PREFIX_PINS = { mdi: '7.4.47', carbon: '11.90.0', logos: '0.0.0', 'simple-icons': '16.35.0', devicon: '2.16.0' } as const;
```

- 每个 `style.*` 必须有 6 个敌人图标 + 1 个 Boss + 8–12 个装饰图标，否则构建失败。
- `alias` 全局唯一；数据层只引用别名，拼错在编译期报错。
- 当前 `src/data/styles.ts` 用软件名字符串绘制磁贴；接入图集后改为图标别名，保留同一套 8 风格/6 原型映射。

### 9.3 管线总览（计划）

```text
assets/icons/manifest.ts
   │ ① icons:fetch（联网；仅开发机，raw/ 提交入库）
   ▼
assets/icons/raw/<prefix>/<name>.svg + index.json（version/license 快照）
   │ ② icons:build（纯离线，可复现）
   ▼
resvg 光栅化（2x，4px padding，normal + silhouette）
   ▼
shelf packer → public/atlas/<atlas>.webp / .png + <atlas>.json
   ▼
license → public/licenses/iconify.md
   ▼
budget → 体积门禁（超限构建失败）
```

- `fetch`：每前缀 1 次批量 JSON（URL 按字母序稳定），超时 8 s、最多 2 次重试；失败回退逐图标 SVG；`--offline` 只用 raw/。
- 图标名白名单 `^[a-z0-9-]+$`，拒绝路径穿越；`PREFIX_PINS` 与缓存版本不一致默认拒绝写入。
- `build` 可离线在 CI 复现；同输入同字节，不写时间戳。

### 9.4 下载与缓存

- 请求粒度：每前缀 1 次批量 JSON；失败回退逐图标 SVG 1 次；429/5xx 不无限重试。
- 缓存键：`raw/<prefix>/<name>.svg` + `raw/index.json`（version/lastModified/license/fetchedAt）。
- 版本固定：`PREFIX_PINS` 与快照比对；不一致要求显式 `--update`，防静默漂移。
- 离线/安全：`--offline` 只用 raw/ 重建；图标名白名单 `^[a-z0-9-]+$`，拒绝路径穿越，只写 `assets/icons/raw/`。

### 9.5 光栅化

- `mono` 图标在烘焙期染色（默认 `#E5E7EB` 或风格色），运行期零 tint；`palette` 保持原色。
- 显示尺寸 ×2（DPR 上限），每帧 4px 透明 padding 防 WebP 渗色；`svgo` 只清元数据，不改 path 精度。
- 同输入同字节：固定 resvg 版本、图集 JSON 不写时间戳。

### 9.6 图集与加载

- 拆图集：`core`（UI + `style.system`）首屏；其余 7 风格各自独立，磁盘挂载过场加载，最多等 1 个过场。
- shelf packer 自研（≤120 行），非 POT；帧 JSON 含 `frame/size/pivot/variant`。
- 图集未到时画“圆角磁贴 + 首字母”，玩法不阻塞；UI 图标用文本符号兜底。

### 9.7 license 报告与回退

| SPDX 族 | 动作 |
| --- | --- |
| CC0-1.0 | 无强制义务，仍列入报告 |
| MIT / Apache-2.0 | 保留版权声明与许可文本，游戏内“关于”可展开 |
| CC-BY / 未知 / 其他 | v1 不引入，构建失败 |

- 产物：`public/licenses/iconify.md`（按 prefix 分组，含作者/license/url/快照版本）与游戏内“关于 → 开源许可”。
- 运行时失败回退：manifest 命中 → fallback 链 → `mdi:application-outline` → 首字母磁贴 → “?”；不崩溃。
- 商标提醒：品牌 logo 仅作描述性/戏仿识别；敏感品牌可换同形不同名。

### 9.8 运行时零网络与失败回退

- 构建期允许 `api.iconify.design`；运行期 CSP `connect-src 'none'`，`dist/**` 不得出现外部域或 `fetch` 调用。
- 失败回退：raw/ 缓存缺失 → 程序化占位；图集加载失败 → PNG → 占位；WebP 不支持 → 整包切 PNG；字体超时 → 系统等宽；SW 缓存损坏 → 删旧缓存并提示。
- PWA 离线自测：断网冷启动 → Hub → 进入 C 盘 → 可操作（发布前必须通过）。

### 9.9 体积预算与门禁

- 预算：`core` 图集 ≤150KB、单风格 ≤80KB、字体 ≤40KB、JS gzip ≤180KB、首屏 ≤500KB、全量 ≤1.6MB。
- 当前（无图集/字体）：JS gzip ≈43KB、CSS gzip ≈5KB、`dist/` 158KB。
- 门禁用 `node:zlib` 实测 brotli/gzip；超限优先降 WebP 质量 → 降图标尺寸 → 去非必要 silhouette 帧，**不得削减玩法内容**。

```js
const CACHE = 'dw.v2';
const SHELL = ['./', './index.html', './manifest.webmanifest'];
self.addEventListener('install', (e) => e.waitUntil(
  caches.open(CACHE).then((c) => c.addAll(SHELL)).then(() => self.skipWaiting())));
self.addEventListener('fetch', (e) => {
  if (e.request.method !== 'GET' || new URL(e.request.url).origin !== self.location.origin) return;
  if (e.request.mode === 'navigate') {
    e.respondWith(fetch(e.request).catch(() => caches.match('./index.html')));
    return;
  }
  e.respondWith(caches.match(e.request).then((r) => r ?? fetch(e.request).then((res) => {
    if (res.ok) caches.open(CACHE).then((c) => c.put(e.request, res.clone()));
    return res;
  })));
});
```

- 当前策略：shell 预缓存；导航请求**网络优先**（离线回退缓存），带 hash 的静态资源 cache-first；避免旧 `index.html` 长期缓存导致新版本不生效。

### 15.2 热路径清单（零分配 / 零查询）

1. 世界实体数组、事件环形缓冲、哈希桶、`out` 查询缓冲全部预分配。
