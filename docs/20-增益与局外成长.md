## 0. 系统总览

### 0.1 两层成长

| 层 | 载体 | 生命周期 | 作用 | 上限 |
| --- | --- | --- | --- | --- |
| 局内 | 增益 `buff` | 单局，死亡/关机后清空 | 构筑、质变、爽感 | 每局 18 / 24 / 30 个（随难度） |
| 局外 | 键帽 `keycap` | 永久，写入存档 | 小属性 + 套装机制 | 87 键全收集 |

**设计红线（ADR-008）**：局外只给属性与套装，不给局内经济、掉落率、RAM 回复、复活；局内增益不跨局。

### 0.2 玩家总属性来源

按属性分别计算：`最终% = 局内加成 + 键帽 eff（软上限后）+ 套装`，攻击/攻速/移速各自结算；DPS = 攻击 × 攻速。
局内与局外同一属性**加算**，不做乘区相乘，避免局外把局内数值放大到失控；键帽按 `00 §7.7` 压缩后再相加（§3.5）；百分比 UI 保留 1 位小数，内部用 float。

## 1. 增益系统框架

### 1.1 触发与流程

| 场景 | 触发 | 形式 | 保底 |
| --- | --- | --- | --- |
| 文件夹通关 | 清空第 3 波 | 暂停，3 张卡选 1 | 无 |
| 磁盘 Boss 通关 | Boss 死亡 | 暂停，3 张**传奇**卡选 1 | 必出传奇 |
| 开局 | 不触发 | 无 | — |

```
清场 → 冻结战场（子弹/敌人保留但不更新）→ 淡入“有可用更新”窗口 → 3 张卡 → 选择 → 安装动画 400ms → 恢复战斗
```

- 选卡期间**完全暂停**逻辑帧，仅 UI 动效与音频继续；未选择前不可关闭窗口，`Esc` 不生效（防误触）。
- 选卡结果、重随次数写入局内 run state，不写存档。

### 1.2 稀有度与权重

| 稀有度 | id | 权重 | 单次占比 | 池数量 | 默认叠层上限 |
| --- | --- | --- | --- | --- | --- |
| 普通 | `common` | 6 | 60% | 12 | 3 |
| 稀有 | `rare` | 3 | 30% | 10 | 2 |
| 传奇 | `legendary` | 1 | 10% | 8 | 1 |

- 权重只在**仍有候选**的稀有度之间归一化：某稀有度池满/耗尽时，把它的权重按比例分给其余稀有度。
- Boss 关固定从传奇池抽 3 张（不按权重）；传奇池不足 3 张时用稀有补足并保持卡面稀有度真实；传奇池全满（8/8）时 Boss 奖励改为 **3 张稀有卡 + 50 碎片**（结算页入账）。

### 1.3 候选生成算法（伪代码）

```ts
function rollOffer(state: RunState, kind: "folder" | "boss"): BuffOffer {
  const pool = kind === "boss" ? LEGENDARY_POOL : ALL_POOL;
  const avail = (r: Rarity) =>
    pool.filter(b => b.rarity === r && state.buffStacks[b.id] < b.maxStacks);
  const picked: BuffDef[] = [];
  while (picked.length < 3) {
    const rarity = kind === "boss" ? "legendary"
      : weightedPick([["common", 6], ["rare", 3], ["legendary", 1]]
          .filter(([r]) => avail(r).length > 0));
    const cand = avail(rarity).filter(b => !picked.includes(b));
    // 候选为空 = 该稀有度已抽空，从其余稀有度按权重补
    const fallback = cand.length ? cand : (weightedPickOtherRarity(rarity, avail) ?? []);
    const pick = pickRandom(fallback, rng);
    if (!pick) break;
    picked.push(pick);
  }
  return { kind, cards: picked, rerolled: false };
}
```

- 同一轮 3 张卡**不重复**；已集齐 `Esc+Enter+Space` 套装时每轮生成 **4 张**（Boss 传奇轮同样 4 张）。
- 重随（键帽套装）重新生成整轮卡、稀有度权重不变，每局 1 次；RNG 走 `00 §7.9` 种子序列，便于复现。

### 1.4 叠层与同乘区

- 同名增益叠层按**加算**累加（如 `缓存命中 ×3` = 攻速 +24%）。
- 同属性增益（攻击%/攻速%/移速%）全部加算后乘到基础值；不同机制（弹数、穿透、暴击、环绕炮台）独立生效、互不乘算。
- 硬上限：攻速攻击间隔 ≥ **0.12 s**（≈8.3 发/s）、单次攻击 ≤ 12 发、穿透 5 层。

### 2.4 传奇触发优先级（同帧竞争）

```
RAM 归零
  ├─ 1. 快照 snapshot 可用 → 回滚 RAM，消耗，2s 无敌，结束
  ├─ 2. 交换分区 swap_partition 可用 → 回满 RAM，消耗，1.5s 无敌，结束
  └─ 3. 均不可用 → 蓝屏
```

- `kernel_panic` 在“受到伤害后、RAM 扣减后”触发；若该次伤害使 RAM 归零，先结算复活，再触发冲击波。
- `blue_screen` 连锁最多 3 次（防无限链）；Boss 与精英不参与处决，仅受 AoE 伤害。

### 2.5 构筑检查（避免无敌组合）

| 组合 | 风险 | 处理 |
| --- | --- | --- |
| 超线程 + 多线程 + 双缓冲 | 弹数爆炸、帧率下降 | 弹数硬上限 12；双缓冲只加伤害不加弹数 |
| 交换分区 + 快照 | 多重复活，难度失效 | 每局复活类最多触发 1 次（先到先得），快照与交换互斥 |
| 虚拟内存 + RAID 0 | RAM 结算为负 | `maxRam = max(1, base + delta)`，下限 1 |
| 内核恐慌 + 蓝屏 | 全屏连锁清场 | 蓝屏连锁 ≤3 次；内核恐慌冷却 6 s |
| 超频 + RAID 0 + 攻速叠满 | 间隔过短 | 攻速硬上限 0.12 s |

### 3.1 键盘与收集目标

- 展示一把 **87 键 TKL 键盘**（7 行布局，`00 §7.7`）；每收集一个键帽，对应键位点亮并可点击查看属性。

### 3.5 属性聚合与软上限

```
raw_atk = Σ(键帽 atk)                 # 套装不计入 raw
raw_as  = Σ(键帽 as)
raw_mov = Σ(键帽 mov)
eff_atk = 18% × (1 − e^(−raw_atk / 18%))
eff_as  = 12% × (1 − e^(−raw_as  / 12%))
eff_mov = 10% × (1 − e^(−raw_mov / 10%))
final   = eff + 套装加成              # 套装在压缩后追加
```

**当前 87 键分布的实际上限（由 §3.3 计算）**

| 属性 | 87 键 raw | 套装追加 | 软上限 cap | 实际生效 |
| --- | --- | --- | --- | --- |
| 攻击 | 15.20% | +3.00% | 18% | **13.26%** |
| 攻速 | 2.64% | +0.00% | 12% | **2.37%** |
| 移速 | 3.30% | +6.00% | 10% | **8.81%** |
| **综合** | — | — | — | **DPS ×1.159（+15.9%）· 移速 +8.81%** |

- 满键盘对 DPS 的综合提升约 **+15.9%**，低于一个传奇增益（+18%），符合“局外锦上添花”的定位。
- 攻击/攻速/移速三类分开压缩；套装属性在压缩后追加；前端展示“当前 → 下一键”的边际收益，避免玩家误以为线性。

## 6. 存档

### 6.1 结构（`desktopwar.save.v1`）

```json
{
  "version": 1,
  "fragments": 1234,
  "keycaps": { "key.escape": 1, "key.q": 1, "key.space": 1 },
  "pity": { "sinceRare": 3, "sinceLegendary": 12 },
  "difficulty": {
    "unlocked": "balanced",
    "cleared": { "eco": true, "balanced": false, "performance": false },
    "firstClearBonus": { "eco": true, "balanced": false, "performance": false }
  },
  "stats": { "runs": 7, "wins": 2, "kills": 2140 },
  "settings": { "musicVolume": 0.6, "sfxVolume": 0.8, "screenShake": true, "reducedMotion": "system", "showHitbox": false, "autoLock": false, "language": "zh-CN" },
  "flags": { "tutorialDone": true, "seenBosses": ["boss.system_update"] }
}
```

> 以上只列代表字段；完整字段（`createdAt/updatedAt`、`stats`/`settings` 全量、`flags.seenEnemies` 等）以实现为准。

- `keycaps` 只存已拥有键（值 1），不存数量；重复在获得时已转碎片。
- `pity.sinceLegendary` 跨局、跨会话累计，出传奇清零；`settings` 与进度同存，便于导出/导入。
- `settings.autoLock` 默认 `false`（自动锁定最近目标）；仅影响瞄准辅助，不改变移动/开火/数值。
- `settings.language: Locale` 默认 `zh-CN`；`en-US` 仅预留，缺失/未知/未发布回退 `zh-CN`；切换立即生效并写档，导入导出保留（30 §11.4）。
- `settings.reducedMotion` 为 `'system' | 'on' | 'off'`，默认 `'system'`（跟随 `prefers-reduced-motion`），用户切换后存显式值。
- 不存局内状态：刷新/关闭页面即视为放弃本局（结算按当前进度折算碎片，见 `10 §10.9`）。

### 6.2 读写与迁移

| 项 | 规则 |
| --- | --- |
| 写入时机 | 结算完成、抽取、键帽入库/套装变化、设置变更（防抖 500 ms） |
| 写入方式 | 先写 `desktopwar.save.v1.tmp`，再原子替换；失败保留旧档 |
| 读取失败 | JSON 损坏/版本过高 → 备份 `desktopwar.save.bad.<ts>` → 新建存档 → toast 提示（版本过高提示更新游戏） |
| 迁移 | 版本号只增不改；`migrate(v)` 顺序执行 v1→v2→…；每步单测 |
| 容量与导入导出 | 存档 < 32 KB；localStorage 配额异常时提示“无法保存”但不阻塞游戏；设置页 JSON 导出/导入，导入前二次确认并备份 |

### 6.3 防呆

- 修改本地存档导致非法 `keycaps` id：读取时过滤并记录日志，不崩溃；属性上限在读取时重算，不信任存档缓存值。
- 时间回拨不影响任何收益（无离线收益）；多标签页以最后写入为准，通过 `storage` 事件提示“另一个页面已更新存档”。

## 8. 边界与异常

| 情况 | 处理 |
| --- | --- |
| 增益池某稀有度全满 / 三张卡都不可用 | 权重转移；Boss 传奇池满 → 3 张稀有卡 + 50 碎片；理论兜底给 50 碎片并跳过 |

| 导入非法 JSON | 校验 schema，失败不改当前档 |
