### 0.4 不变量（任何 PR 违反即打回）
1. **风格只换皮**：`style` 不改数值、数量、掉落、时长（00 §8 硬约束、ADR-003）。
2. **难度只改 `D`/磁盘数/结算倍率**：不改行为脚本、不改关卡时长目标（00 §7.4）。
3. **数值单一来源**：玩法代码禁止硬编码 Canon 数值，一律从 `src/data/formulas.ts` 的 `K/D/M` 与 `enemyHp/enemyDamage/enemySpeed/enemyAtkSpd/spawnCount` 纯函数取。
4. **无冲刺/无闪避/无射击键/无弹药**（00 §7.1、§11、ADR-007）；移动不加加速度。
5. **确定性**：局内随机只能经 `rng.fork(stream)`，流名固定为 `style / wave / buff / drop / telegraph`（00 §7.9）。
6. **表现与逻辑分离**：渲染/音频/震动/震屏只读事件，不得回写模拟状态。

## 1. 分层架构
### 1.1 六层模型
```
L6 Meta      : 结算 raw/mult → 碎片、键帽入库、存档、Hub（20 负责）
L5 Flow      : scene / run phase / wave 状态机，硬暂停栈（§2）
L4 Resolve   : collision → damage_resolve → death_check → revive_hook → clear_check → drops（§10）
L3 Simulate  : ECS 系统（control/aim/weapon/bullets/enemy_ai/spawner）
L2 Config    : 数据表 enemies/waves/bosses/styles + balance 纯函数
L1 Input     : WASD/mouse/touch sticks → input_intent（§3）
事件上行（只读）→ 40 表现层；命令下行（单帧）
```

### 1.2 层间契约
| 接口 | 生产者 → 消费者 | 形状 | 频率 |
| --- | --- | --- | --- |
| `IntentSource.sample()` | L1 → L3 | `Intent` | 每逻辑帧 1 次 |
| `Sim.step(dt)` | L5 → L3/L4 | 无返回值，内部按 §1.3 顺序推进 | 每逻辑帧 |
| `EventBus.flush()` | L3/L4 → 40/20/L5 | `GameplayEvent[]`（§13.1） | 每帧末 1 次，合并同类 |
| `BuffRuntime.stats()` | 20 → L3 | 只读 `Record<StatKey, number>` | 缓存，变更时失效 |
| `RunResult` | L4 → 20/40 | `RunResult`（§10.9） | 每局 1 次 |
| `WavePlan` | L2 → L3 | 已抽样的 `WaveDef`（含随机结果） | 每波 1 次 |

### 1.3 单帧管线（固定顺序，实现必须照抄）
| # | 系统 | 职责 |
| --- | --- | --- |
| 1 | `input_system` | 采样 WASD/鼠标/双摇杆 → `Intent`（移动与瞄准分离，唯一入口） |
| 2 | `player_control` | `pos += move * 320 * dt`；边界 clamp（玩家先行，延迟最低） |
| 3 | `aim_system` | 手动 `aim_intent` 优先；设置开启且空闲 ≥0.4 s 时软锁最近敌人（§4.2） |
| 4 | `weapon_system` | `cd -= dt`，`cd<=0` 则生成字符弹并重置 `cd += interval` |
| 5 | `player_bullet_move` | 位置积分、生命周期、出屏回收（移动先于碰撞） |
| 6 | `enemy_ai` | 追踪/定点/前摇计时/召唤计时，只写敌人意图不改世界 |
| 7 | `enemy_fire` | 按 `pattern` 生成敌方子弹，生成前检查单敌人 8 发与全局 240 发上限，超限跳发 |
| 8 | `enemy_bullet_move` | 位置积分、出屏/激光计时回收 |
| 9 | `spawner_system` | 波次队列出队、出生点选择（距玩家 ≥`D-08`），保证 0.6 s 节奏稳定 |
| 10 | `collision_player_bullets` | 只收集命中对（不结算），保证同帧伤害可合并 |
| 11 | `damage_resolve_enemies` | 命中落账、破盾、死亡、分裂/召唤、掉落排队（敌人先死，§10.8） |
| 12 | `collision_hostile` | 收集敌方子弹/接触命中（不结算） |
| 13 | `damage_resolve_player` | `invuln>0` 全部忽略；否则取本帧最高伤 1 次 → `ram -= dmg` → 赋 1.0 s 无敌（唯一改 `ram` 处） |
| 14 | `death_check` | `ram<=0` → `revive_hook` → 蓝屏；`clear_priority` 先判通关（§10.5、§10.8） |
| 15 | `pickup_economy` | 掉落拾取、击杀计数、无伤标记 |
| 16 | `clear_check` | 波/关清空判定 + 3 s 看门狗（最后判，避免帧内抖动） |
| 17 | `cleanup` | 退场、对象池归还、越界移除 |
| 18 | `events_flush` | 合并后一次性上抛 40/20（表现层不得早于结算） |

> 依据：固定步长与插值见 00 §9；伤害统一落账是 §10.2 编号唯一性的前提。

## 2. 状态机
### 2.1 顶层（scene）
```
boot ─assets_ready─► hub ─start_run─► run_init ─► run
                     ▲                            │
                     │                            ├─ ram==0 且无复活 ─► bsod(2.5 s) ─┐
                     │                            └─ 最后一层 boss 死亡 ─► shutdown(2.0 s) ─┤
                     └────────── settlement ◄── run_end ◄────────────────────────────────┘
```

### 2.2 局内相位（run phase）
```
run_init ─► disk_intro ─► folder_intro ─► wave ─► wave_clear ─┐（×3 波）
    ▲                                                        │
    │                          folder_clear ─► buff_pick ────┤ 第 1–4 个 → 回 folder_intro
    │                                                        └ 第 5 个 → boss_intro ─► boss ─► boss_clear ─► disk_clear
    └───── disk_clear：还有下一层 → disk_intro；最后一层打完 → shutdown
```

### 2.5 子状态机
```
wave  : idle ─spawn_tick(0.6 s)─► spawning ─queue empty─► draining ─alive==0─► done
         draining + 3 s 看门狗 → force_clear（防卡关，§12.15）
enemy : spawn_in(0.4 s，不可选中/不射击) ─► active ─┬─► windup(0.35/0.8 s) ─► fire ─► active
                                                     └─► dying(0.12 s) ─► removed
         精英额外：spawn_in 结束 → windup(0.8 s) ─► active
```

> Canon 引用：精英出场前摇 0.8 s、受击硬直更低（00 §7.2）。

### 2.6 硬暂停栈（orthogonal 于相位）
| 来源 | id | 是否冻结模拟 | 是否计时 | 恢复保护 |
| --- | --- | --- | --- | --- |
| `Esc` / 移动端右上角 | `pause.user` | 是 | 冻结 | 无额外无敌（防暂停躲弹） |
| 页面不可见 >1 s | `pause.hidden` | 是 | 冻结 | 同上 |
| 窗口失焦 / 指针离开 | `pause.blur` | 是 | 冻结 | 清空 `move/aim`，玩家不瞬移 |
| 增益三选一 | `pause.buff` | 是 | 冻结 | UI 层，非玩家可取消 |
| 系统对话框/来电 | `pause.system` | 是 | 冻结 | 清空双摇杆触摸状态，重按重新生成 |

> 栈规则：任一 `pause` 存在 → `Sim.step` 不执行，仅渲染最后一帧 + 覆盖层；`resume` 时重置 `intent`、保留 `invuln` 剩余值（不补时不扣时）。

### 2.7 类型落点
运行类型以 `src/game/types.ts` 与 `src/game/run.ts` 的导出为准；本文只描述状态与规则，不复制接口定义。

## 3. 移动、瞄准与输入
### 3.1 统一输入模型
桌面与移动共用同一 `Intent`：**移动向量与瞄准向量分离**，自动开火，无射击键（ADR-007/011）。玩法只消费 `move/aim/aimActive/pause`，技术侧完整字段见 `30 §7.1`。
```ts
interface Intent {
  move: Vec2;          // 归一化移动向量（WASD / 左摇杆），长度 0..1
  aim: Vec2;           // 归一化瞄准向量（鼠标 / 右摇杆），长度 0..1
  aimActive: boolean;  // 本帧是否有手动瞄准输入
  pause: boolean;
}
```
- 初始 `aim=(0,-1)`（向上）；无手动瞄准时保持最后有效方向，不自动转向。
- 输入层只产 Intent，不直接改位置或朝向；移动/瞄准的最终裁决在 §3.2/§3.3 与 §4.2。

### 3.2 桌面：WASD 移动 + 鼠标瞄准
| 项 | 规则 | 依据 |
| --- | --- | --- |
| 移动 | `WASD`/方向键，8 向，320 px/s，无加速度；对角线归一化（×1/√2） | 00 §3、§7.1 |
| 瞄准 | 鼠标逻辑坐标相对玩家光标 → 单位向量；鼠标停止移动但玩家移动时仍每帧按相对位置重算；鼠标距玩家 <24 px 时保持上一方向 | ADR-011 |
| 准星 | 绘制在鼠标逻辑坐标；**玩家光标不跟随鼠标**，只按移动向量移动 | 00 §10.2 |
| 系统指针 | `canvas { cursor:none }`；准星由 Canvas 绘制 | 00 §10.2 |
| 边界 | 玩家光标 clamp 在 16 px inset 内；准星可贴边（只影响方向） | `D-03` |
| 失焦 | 清空 `move/aim`，`pause.blur`；恢复后不瞬移 | §12.3 |
| 判定点 | 玩家光标中心，半径 3 px；准星不参与受击判定 | 00 §7.1 |

### 3.3 移动端：仅横屏双摇杆
| 项 | 规则 | 依据 |
| --- | --- | --- |
| 屏幕方向 | **仅横屏**；竖屏 → `pause.system` + 旋转覆盖层，不进入战斗 | 00 §3、§12 TBD-01 |
| 摇杆 | 浮动双摇杆：左半屏触摸生成移动摇杆，右半屏生成瞄准摇杆；底座直径 96 px、摇杆头 44 px、行程 48 px、死区 8 px | `D-04`~`D-06` |
| 移动 | 左摇杆偏移 → `move`；松手 → 移动立即停止（无惯性） | 00 §7.1 |
| 瞄准 | 右摇杆偏移 → `aim`；松手 → 保持最后方向，不自动锁敌（除非开启设置） | ADR-011 |
| 自动开火 | 始终自动开火；摇杆只负责移动/瞄准，无射击键 | ADR-007 |
| 多指 | 左右各一指；第三指忽略；`touchcancel` 只清对应摇杆 | §12.4 |
| 安全区 | 摇杆底座中心距底部/侧边 ≥ 安全区 + 96 px；HUD 避让 | 40 §12 |
| 方向锁定 | manifest `orientation: landscape` + 旋转覆盖层已实现；`screen.orientation.lock('landscape')` 为计划增强，失败不阻塞 | 30 §13.4 |

### 3.4 输入优先级与边界
- 桌面鼠标移动只影响瞄准，不影响移动；WASD 与鼠标可同时输入，互不抢占。
- 移动端左右摇杆独立；无“最后输入者覆盖另一通道”的互斥。
- `Esc` 暂停；切后台/失焦清空两路 Intent，恢复不补帧。
- **自动锁定最近目标**（设置项，默认关）：仅当 `aimActive=false` 持续 ≥0.4 s 时，锁定玩家 480 px 内、屏幕内最近的敌人；转向速度 360°/s 软锁。手动瞄准输入当帧立即退出锁定（`D-01`/`D-07`/`D-32`）。

### 3.5 受击与无敌
| 项 | 规则 | 依据 |
| --- | --- | --- |
| 判定半径 | 3 px（玩家光标中心） | 00 §7.1 |
| 受伤后无敌 | 1.0 s，期间免疫一切伤害与接触 | 00 §7.1 |
| 视觉反馈 | 每 0.25 s 切换显隐 = 2.0 Hz（≤3 Hz 硬约束） | 00 §10.2 |
| 无敌覆盖 | 复活（交换分区/快照）给独立无敌，与受击无敌取 `max` 剩余时间，不叠加 | 00 §7.6 |
| 受伤瞬间 | 40 层：屏幕震动 3 px / 120 ms、红色边缘闪 1 帧、错误音；**逻辑不减速** | `D-13` |

### 3.6 手感红线
1. 判定点必须可见（光标中心 1 px 高亮点），不允许“看不见的判定”。
2. 移动/瞄准分离：鼠标或右摇杆不改变玩家位置；左摇杆/WASD 不改变瞄准方向。
3. 默认**不做**自动索敌/吸附；自动锁定只在设置开启且手动空闲时生效，避免“抢手”。
4. 移动端不出现“手指遮挡准星”的固定锚点方案；准星始终由右摇杆方向绘制。

## 4. 自动开火与字符弹
> Canon 引用：00 §7.1（攻击力 10、攻击间隔 0.8 s、面板 1.25 发/s、子弹速度 900、子弹半径 4、初始弹数 1、无穿透、无限弹药、移动速度 320 px/s）

### 4.1 开火循环
| 项 | 规则 | 依据 |
| --- | --- | --- |
| 触发 | 自动，无射击键；进入 `wave`/`boss` 相位即开火 | ADR-007 |
| 间隔 | `interval = max(0.12, 0.8 / (1 + fire_rate_pct))`（20 P-101 硬上限）；首帧 `cd=0` 立即开火 | 00 §7.1、ADR-001 |

### 4.2 瞄准解算 `aim_policy`
```
默认（autoLock = false）：
  aim_dir = normalize(aim_intent)
  若 |aim_intent| < 死区 → 保持 last_aim（初始向上）
  手动输入立即生效，无粘性、无提前量

开启 autoLock（设置项，默认 false）：
  条件：aimActive == false 持续 ≥ 0.4 s（D-01）
  目标：玩家 480 px 内、屏幕内、最近敌人（D-07）
  转向：360°/s 软锁（D-32）；目标死亡/离屏 → 立即放弃并保持 last_aim
  退出：任一手动瞄准输入当帧退出锁定；不改变移动
```
- 自动锁定**只影响瞄准方向**，不改变玩家位置、不改变自动开火节奏。
- 无敌人/无手动输入 → 保持最后方向；从未输入 → 向上。
- 禁用“预判提前量”，直线弹道不做提前瞄准。

### 4.3 伤害与扩展点
```
单发伤害 = 10 × (1 + attack_pct) × (1 + crit_chance × crit_mult)   // 暴击在 20 定义
命中数   = 1 + bullet_count（多弹）
穿透     = pierce（命中后不销毁，可继续命中，默认 0）
```
| 扩展点（由 20 提供，玩法只消费） | 字段 | 默认 | 上限 |
| --- | --- | --- | --- |
| 攻击力 | `attack_pct` | 0 | 键帽软上限 18%（00 §7.7） |
| 攻速 | `fire_rate_pct` | 0 | 软上限 12% |
| 多弹 | `bullet_count` | 1（00 §7.1） | ≤ 12（`D-02`，与 20 P-102 一致） |
| 穿透 | `pierce` | 0 | ≤ 5（与 20 P-103 一致） |
| 暴击 | `crit_chance` / `crit_mult` | 0 / 1.5（`D-15`） | 由 20 定义 |
| 弹速 | `bullet_speed` | 900（00 §7.1） | 900–1200 |

### 5.2 波次预算中性校验
00 §7.2 规定"6 种原型共享数值预算"，因此原型允许在 HP/速度/火力间重分配，但**单波有效 HP 不得超预算**：
```
有效 HP 预算 = spawnCount × HP0 × M × [0.95, 1.05]
有效 HP      = Σ (数量 × hp_scale) × HP0 × M
```
| 波次 | 编成权重 `w` | Σ(w×hp_scale) |
| --- | --- | --- |
| W1 | popup .60 / notifier .40 | 0.60+0.40 = **1.00** |
| W2 | popup .25 / notifier .25 / adware .25 / updater .15 / cache .10 | 0.25+0.25+0.25+0.09+0.16 = **1.00** |
| W3 | popup .35 / notifier .25 / adware .20 / trojan .15 / cache .05 | 0.35+0.25+0.20+0.15+0.08 = **1.03** |

> 召唤物（updater）与 trojan 子体已计入 `hp_scale`；分裂子体血量 = 父体 40%（`D-18`），故 trojan 有效 HP = 0.55 + 2×0.22 = 0.99。

### 5.3 六原型行为细则
- **`popup`（弹窗）— 追击型**：以 `enemySpeed×1.00` 直线朝玩家当前位置移动，每 0.25 s 更新朝向（`D-19`）形成轻微过冲弧线，可被绕后甩开；无子弹，接触伤害 1，受击无击退；屏幕外环出生 + `spawn_in` 0.4 s 磁贴落下；离屏 >200 px 且玩家不在同侧 → 5 s 后重新进入（`D-20`，防挂机）。
- **`notifier`（通知）— 炮台式**：定点不动，每 `0.8/enemyAtkSpd` s 发 1 发朝玩家当前位置的弹（弹速 240，`D-21`）；前摇 0.35 s 时磁贴顶部亮 1 px 进度条（可读性红线，必须可见）；同屏子弹达 8 发 → 暂停射击直到回收（00 §7.2）。
- **`adware`（广告）— 扇形压制**：定点，每 `0.8/enemyAtkSpd` s 发 3 发、扇角 ±15°（总 30°）、弹速 200、前摇 0.35 s；3 发在 0.08 s 内依次生成，但**同一帧只生成 1 发**，避免瞬间封路；出生在可视安全区的中场位置，压缩玩家上半场空间。
- **`trojan`（木马）— 分裂型**：以 51 px/s 缓慢追踪，接触伤害 1；死亡立即原地分裂 2 只子体（HP = 父体 40%、速度 ×1.25、`hp_scale` 0.22、`split_depth=1` 不再分裂）；子体继承皮肤但缩小 70%，计入击杀数、不掉落。
- **`cache`（缓存）— 高血撞击**：HP ×1.6、速度 ×0.6（36 px/s 基准）、无子弹仅撞击；受击硬直 ×0.5，被打不退反进；视觉为磁贴半透明 + 四角括号；同屏 ≤ 3（`D-22`），防堵死通道。
- **`updater`（更新器）— 召唤型**：HP ×0.6、速度 ×0.9，绕可视安全区内的固定基点做 86 × 52 px 椭圆运动（`D-35`）；每 8 s 召唤 1 只 `popup`（HP = 0.5× 正常，`D-23`），同时最多 1 只召唤物、全程最多 2 只；召唤有 0.6 s 前摇（磁贴变形成进度条），可被打断（受伤害 → 取消并重置计时）；召唤物计入同屏上限，超限则本次失败。

### 6.4 刷怪节奏
- 队列按 0.6 s 间隔逐个出队；`wave` 相位开始先出第 1 只（t=0），不额外等 0.6 s。追击型出生点为屏幕外环随机（上/左/右权重 40%/30%/30%，底部 0，避免从玩家背后贴脸生成）；`notifier`/`adware`/`updater` 出生在可视安全区内，避免无入场位移的敌人滞留场外。
- 编成顺序用 `rng.fork('wave')` 一次性洗牌，保证同种子可复现（00 §7.9）；W3 精英固定最后 1 个出队（t = 0.6×n），给玩家预告（40 层警报音）。

### 6.6 清场判定
- 波次完成 = `spawner.queue.empty && alive_enemies == 0`；`draining` 持续 > 3 s 仍有存活 → `force_clear`（防不可达敌人卡关，§12.15）；`wave` 相位 > 90 s 且 `alive==0` 但队列非空 → 强制出队（防 spawner 卡死）；强清 = 相位切换时敌方子弹全清、敌人淡出、掉落保留。
- 敌方子弹**不参与**清场判定（否则玩家会因残弹被卡住），但清场时给 0.25 s 无敌缓冲（`D-26`），防止"最后一帧被残留弹打死"。

### 8.4 逐个机制草案
- **`boss.system_update` 系统更新（C: 固定登场，全玩家第一个 Boss）**：P1 以 40 px/s 横移，每 `1.2/atkSpd` s 发 `pat.ring8`，每 8 s 召唤 `bossSummonCount` 只 `updater`；P2 每 20 s 触发**重启**——全屏敌弹清空、小怪退场、Boss 停滞 5 s 不攻击（可全力输出），随后 `pat.ring16` 继续；意图：教学 Boss，教"读招 + 抓窗口"。
- **`boss.popup_king` 弹窗之王（D: 起随机）**：P1 定点中场，每 6 s 向四周喷 3 组 `pat.fan3`（错开 0.3 s），每 10 s 固定召唤 3 只 `popup`（不占召唤公式）；P2 每 6 s 传送到四角之一（0.5 s 预警圈），落地 1.2 s 内不攻击，随后 `pat.aimed_fan5` 三连；惩罚：同屏 >8 只 popup 时 Boss 获 20% 减伤（`D-28`）。
- **`boss.dependency` 依赖地狱**：P1 本体**无敌**，场上 3 个依赖节点（HP = `60×M`，定点，各发 `pat.aimed1`），节点全破 → 本体破盾 4 s（可输出）后节点重生；P2 节点 5 个 + 每 6 s 相邻节点连线扫射（1.0 s 预警）；节点总 HP 为 Boss 的 30%（3×60/600），保证窗口可期待。
- **`boss.memory_leak` 内存泄漏**：P1 本体 40 px/s 游走，每 5 s 随机生成 1 个不可摧毁"内存块"（半径 40、持续 20 s），每 `1.2/atkSpd` s 发 `pat.spiral`；P2 每 4 s 生成块、存活块每 3 s 向四周发 4 发慢弹（`pat.homing_slow` 减配），每 15 s **GC 清扫**——清空块并 3 s 不生成（输出窗口）；意图：把走位空间当可消耗资源，用清扫防死局。
- **`boss.corruption` 格式错乱**：P1 每 1.6 s 发 `pat.wall_rows`（9 发横排、行间错位 40 px、可穿缝隙），本体 40 px/s 斜移；P2 每 12 s"旋转排版"——弹幕行转竖排、方向 +90° 并叠加交叉行（1.0 s 明确预警）；公平性：错位视觉只作用于背景与装饰层，战斗层不位移（否则瞄准不可信）。
- **`boss.false_positive` 误报风暴**：P1 每 6 s 一次 `pat.laser_sweep`（2.0 s 预警红线 → 0.4 s 伤害带扫 90°），间隙 `pat.aimed1` 补压；P2 十字双扫描（交错，不同时封死四象限）+ 每 9 s 召唤 2 只 `notifier`（"隔离区"）；公平性：伤害带 ≤ 24 px，预警色为危险红 `#F87171`（00 §10.1）。
- **`boss.unsaved` 未保存的工程**：P1 血条下方常驻"自动保存"倒计时 25 s，归零 → 全屏 `pat.ring16` 爆发（可躲、非必死）并清空场上增益计时；归零前对 Boss 造成 ≥ `0.12 × maxHP` 伤害 → **打断保存**（`D-29`），Boss 硬直 2 s 并重置倒计时；P2 倒计时 18 s、阈值 `0.15 × maxHP`、爆发改为 `pat.ring16 + pat.wall_rows`；意图：不引入新资源，用 DPS 检定制造紧张，打断是正反馈。
- **`boss.reconnect` 断线重连**：P1 每 7 s "丢包"——本体消失 1.5 s（不可命中），0.5 s 预警后在随机边缘重连，重连后 2 s 攻击间隔 ×1.5，常驻 `pat.homing_slow`（3 个慢速追踪包）；P2 消失频率 5 s、每次重连分裂 2 只 `popup`、追踪包 5 个；意图：把"不可选中"变成节奏，重连后 2 s 是输出窗口。

| 6 | 玩家受击判定 | `invuln>0` → 全部丢弃；否则取本帧**最高单次伤害** 1 次 |
| 7 | `ram -= dmg` | 整数扣减；`evt.ram_changed` |
| 8 | 赋无敌 | `invuln = max(invuln, 1.0)` |
| 9 | 死亡判定 | `ram <= 0` → 走 §10.5 |
| 10 | 清场判定 | 波/关/Boss；`clear_priority` 先判通关（§10.8） |
| 11 | 事件 flush | 一次性上抛 |

### 10.3 RAM 扣减与显示
| 项 | 规则 |
| --- | --- |
| 类型 | 整数 0–5（00 §7.1） |
| 扣减 | 一次受击 = 一次扣减（`ram -= dmg`），不按子步累加 |
| 显示 | 5 格电池式 RAM 条；受伤格闪白 120 ms；≤2 格时变危险红 `#F87171` |
| 溢出/归零 | 上限 5，超出丢弃（§7.6）；归零立即进入死亡判定，本帧剩余系统不再对玩家生效 |

### 10.4 无敌帧规则
`invuln_left = max(invuln_left, 1.0)`（受击）/ `max(invuln_left, 1.5)`（交换分区复活，00 §7.6）/ `-= dt`（暂停时冻结）；伤害入口统一检查 `if (invuln_left > 0) return SKIP;`。
- 无敌期间不受子弹/接触/激光伤害；玩家无受击位移（§3.6），**不存在**"被击退"；视觉：2.0 Hz 闪烁 + 光标外围 1 px 白描边。

### 10.5 死亡判定与复活钩子（`revive_hook`）
```
死亡判定（ram<=0）
 ├─1 clear_priority：本帧已击杀最后 Boss / 清空最后一波？
 │     → 是：走通关流程（不蓝屏），RAM 记为 1 用于结算展示（D-30）
 ├─2 遍历 revive_hook（优先级：buff.snapshot > buff.swap_partition；每局合计最多 1 次）
 │     ├─ buff.snapshot（传奇，每局 1 次）：回滚到最近快照 RAM → invuln = 2.0 s → evt.revive
 │     ├─ buff.swap_partition（传奇，1 层，每局 1 次，00 §7.6）
 │     │     消耗增益 → ram = 5 → invuln = 1.5 s → evt.revive → 继续本局
 │     └─ 其他复活类增益（20 定义，按同一契约注册，先到先得）
 ├─3 无钩子接管 → 蓝屏（bsod）
```
| 复活契约 | 字段 | 说明 |
| --- | --- | --- |
| `id` | string | 增益 id，用于结算统计 |
| `restore_ratio` | 1.0 | 交换分区为 100% |
| `invuln` | 1.5 | 秒 |
| `max_triggers_per_run` | 1 | 每局复活类合计仅 1 次（多件时按 snapshot → swap_partition 取最高者） |
| `consume` | true | 触发即移除该增益层 |

### 10.6 蓝屏流程（`bsod`）
| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| 冻结 | 0.35 s | 全场慢放至 0.2×（视觉），逻辑已停 |
| 切场 | 0.2 s | 蓝底 `#0A5BD3` 淡入 |
| 文案 | 00 §10.3 逐字 | `:(` / 终止代码 `DESKTOP_WAR_RAM_EXHAUSTED` / 失败操作 `desktopwar.exe` |
| 进度 | 2.5 s | `0% 完成` → `100% 完成`，可点击跳过 |
| 结算 | — | `evt.run_end` → settlement（本次开机报告） |

### 10.7 通关流程（`shutdown`）
| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| 清屏 | 0.6 s | 敌方子弹/敌人淡出、Boss 碎裂 |
| 文案 | 00 §10.3 逐字 | `正在关机...` / `所有程序已安全关闭。` / `计算机已安全关机` |
| 停留 | 2.0 s | 可点击跳过 |
| 结算 | — | `cleared = true`，`mult ×1.25`（00 §7.8） |

### 10.8 同帧竞争裁决（`clear_priority`）
| 竞争 | 裁决 | 理由 |
| --- | --- | --- |
| 最后一击击杀 Boss vs 玩家同帧死亡 | **通关优先**；玩家死亡不触发蓝屏，RAM 展示为 1 | 避免"赢了却蓝屏"（00 §2 死得明白） |
| 最后一波清空 vs 玩家同帧死亡 | 同上（通关优先于本关死亡） | — |
| 玩家死亡 vs 敌人死亡 | 敌人先结算（击杀/掉落保留） | 结算数据完整（00 §7.8 用击杀数） |
| 多个复活钩子同时可用 | 取优先级最高 1 个，其余不消耗 | 每局复活上限 1 |
| 复活瞬间再次受击 | 1.5 s 无敌拦截 | 00 §7.6 |

## 11. 节奏与体验曲线
### 11.1 单关节拍
`folder_intro 1.0s` → W1（约 9 s）→ 1.5 s 间隙 → W2（约 15 s）→ 1.5 s 间隙 → W3（约 20 s，精英最后）→ 1.0 s 奖励；预算见 §6.7。表现层：入场打字机音、W2 警示音上扬、W3 底鼓加密、精英警报 + 震屏、清场下行和弦、奖励更新窗口。

### 11.2 压力曲线（单磁盘）
```
压力 5 │                                ██
     4 │            ██      ██          ██
     3 │      ██    ██  ██  ██    ██    ██
     2 │  ██  ██    ██  ██  ██  █ ██    ██
     0 └──F1────F2────F3────F4──F5──Boss──► 时间（每关 +0.5 压力；F5 额外 +1；Boss 峰值；每关结束 RAM+1 与三选一 = 松弛点）
```

### 11.3 Boss 前压力与休息点
| 设计 | 做法 | 目的 |
| --- | --- | --- |
| Boss 前压力 | 第 5 个文件夹 W3 强制含 `cache`/`trojan`（`D-25`）；W2 权重里 `cache` 提到 .15 | 让玩家带着"低血进入 Boss"的紧张 |
| 进入 Boss 前缓冲 | `folder_clear` 的 RAM+1；`boss_intro` 1.4 s 内不进入战斗更新 | 不被"过场偷袭"（§12.6） |
| 关内松弛 | `wave_clear` 1.5 s 清屏 + 音效下行，期间仍可操作 | 呼吸点但不冻结 |
| 关外松弛 | 增益三选一（硬暂停）+ 层间过场 | 决策代替操作 |
| 无"安全走廊" | 不给回血道具、不给补给箱（00 §11 无局内商店） | 保持 RAM 稀缺性 |

### 11.4 疲劳管理
- 单关 ≤ 55 s（高性能前两盘例外 60–75 s），Boss ≤ 75 s，任何连续战斗段 ≤ 90 s 必有硬暂停点。
- 每层磁盘结尾（Boss 后）必给传奇三选一 + 键帽，形成"章节完成"锚点；无长过场（≤ 4 s，可跳过），符合"3 秒开玩"（00 §2）。

### 13.2 与 `20` 的接口（增益/键帽）
```ts
type StatKey = 'attack_pct' | 'fire_rate_pct' | 'bullet_count' | 'pierce' | 'crit_chance'
  | 'crit_mult' | 'move_speed_pct' | 'invuln_bonus' | 'bullet_speed' | 'ram_max' | 'kill_damage_pct';
type HookKey = 'on_run_start' | 'on_folder_clear' | 'on_boss_phase2' | 'on_player_fire'
  | 'on_bullet_hit' | 'on_enemy_kill' | 'on_player_damaged' | 'on_ram_zero' | 'on_run_end';
interface BuffRuntime {
  stats(): Readonly<Record<StatKey, number>>;   // 已应用键帽软上限（00 §7.7）
  subscribe<K extends HookKey>(k: K, fn: (ctx: HookCtx[K]) => void): () => void;
  resolve_revive(ctx: ReviveCtx): ReviveResult | null;   // 见 §10.5
  roll_buff_options(rarity: 'normal' | 'rare' | 'legendary', n: 3): BuffCard[];
}
```
- 玩法**只**读 `stats()` 与注册钩子，不直接读写 20 的增益数据；防御性把 `bullet_count` clamp 到 12、`pierce` clamp 到 5（§4.3）；键帽属性与套装在 20 内合成后统一经 `stats()` 暴露，玩法不感知键帽。
