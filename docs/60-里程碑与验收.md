## 2. 已完成验收

### 2.1 内容与数值

- 数据表数量核对：30 增益 / 87 键帽 / 8 风格 / 8 Boss / 6 敌型。
- `src/data/formulas.ts` 与 `00 §7.3` 逐字一致；`tests/formulas.test.ts` 覆盖 K/D/M 与伤害/数量缩放。
- 碎片公式与满通关示例（863 / 1,523 / 2,412）在 `00 §7.8`、`20 §4.1`、`50 §5.1` 三处一致。
- 固定文案：蓝屏 `DESKTOP_WAR_RAM_EXHAUSTED`、通关“计算机已安全关机”逐字落地。

### 2.2 可玩闭环

- 启动 → Hub → 难度 → 磁盘 C: → 5 文件夹（每关 3 波）→ Boss → 层间过场 → … → 蓝屏/安全关机 → 开机报告 → Hub。
- 死亡/通关均结算碎片；局内键帽获得即入库、死亡保留。
- 暂停（任务管理器）、设置、放弃本局、再来一局、返回桌面均可用。
- 局外：87 键键盘、抽取（单抽/十连/保底/重复转化）、图鉴、设置、存档导出/导入/重置、难度解锁。

### 2.3 平台

- 桌面：WASD/方向键移动 + 鼠标瞄准，自动开火。
- 移动端横屏：左摇杆移动 + 右摇杆瞄准；竖屏显示“请旋转设备至横屏”并暂停。
- PWA：manifest `orientation: landscape`；Service Worker 首次加载后按同源缓存资源。
- 运行时 0 第三方依赖、0 外部网络请求、0 音频文件。

### 2.4 文档一致性

- `python tools/check_docs.py` 校验文件、公式、计数、固定文案、路径、状态与行数预算。
- 版本号、状态词、实现路径三处统一：本文、`docs/README.md`、各文档页眉。

## 7. 定义完成（DoD）

一个功能只有同时满足以下条件才算完成：

1. 行为符合对应设计稿，设计稿无未决冲突。
2. 有自动化测试或明确的手工验收步骤。
3. 桌面与移动端均验证（涉及 UI/输入时）。
4. 不突破体积/性能预算。
5. 文案、稀有度颜色、图标无占位（当前图标占位是已知例外）。
6. 存档兼容（涉及持久化时）。
7. 更新受影响的文档章节或 ADR，并保持版本号一致。
